# Техническая архитектура (MVP)

> Статус реализации по каждому компоненту — см. README.md, раздел "Статус
> реализации". Коротко: диалоговый движок, STT/TTS, Calendar/CRM и БД уже
> реализованы и покрыты тестами; реальная телефония (Asterisk) — ещё каркас,
> ждёт настоящего SIP-номера.

## Голосовой пайплайн одного звонка

```
Телефония (SIP/PBX) → STT (речь→текст) → LLM-диалоговый движок (Claude API,
  системный промпт = "профиль" бизнеса + контекст из CRM/базы знаний) → TTS
  (текст→речь) → обратно в телефонию
                     ↕
         Backend: сценарии, function-calling в CRM/календарь (запись, перенос),
         логирование звонков, эскалация на человека при затруднении
```

## Телефония

Для MVP — виртуальный номер + SIP-транк через международного провайдера с
DID Узбекистана (например DIDWW или аналог), либо прямой SIP-транк от
локального оператора (Beeline/Ucell/Uztelecom предоставляют бизнес-VoIP/SIP).

Оркестрация звонков (IVR, приём/исходящие, запись разговора) — self-host
**Asterisk/FreeSWITCH** на минимальном VPS: дешевле для MVP, чем облачная
платформа (Twilio/Vonage), и даёт полный контроль над записью звонков —
важно из-за требования локализации персональных данных (см. `compliance.md`).

## STT/TTS для узбекского и русского

- **Yandex SpeechKit** — основной вариант: поддерживает распознавание и
  синтез речи на узбекском (латиница) и русском, есть телефонные (8kHz)
  модели — один поставщик для обоих языков.
- **Aisha AI** и **NeuronAI** — узбекистанские сервисы, специализирующиеся
  именно на узбекском STT/TTS (в т.ч. диалектная речь), REST API — тестировать
  как основной или резервный вариант для узбекского языка.
- **Google Cloud Speech-to-Text** — также поддерживает узбекский, резервный
  вариант.
- Решение для MVP: Yandex SpeechKit как основной провайдер (RU+UZ, один
  контракт), Aisha AI/NeuronAI — A/B тест качества для UZ-диалогов; выбрать
  победителя по итогам пилота.

## LLM / диалоговый движок

Claude API с function calling:
- запись/перенос/отмена брони в календаре;
- чтение базы услуг/курсов/цен клиента (RAG, не хардкод в промпте);
- эскалация звонка на человека (по ключевым словам, таймауту, явной просьбе).

Системный промпт — на русском и узбекском, чёткий сценарий по профилю
бизнеса (`courses` / `salon` / `sales`), см. `backend/app/agent/profiles/`.

## Интеграции (booking/CRM)

- **Google Calendar API** — запись на приём, самый быстрый вариант для MVP.
- **amoCRM / Bitrix24 API** — популярны в Узбекистане/СНГ, коннектор для
  лидов из холодных звонков (следующий этап после MVP на Calendar).

## Хранение данных

Отдельная БД (Postgres) на сервере, физически/юридически привязанном к
Узбекистану (локальный VPS-провайдер или дата-центр в РУз) — там же логи
звонков и (опционально) аудиозаписи, с шифрованием и retention-политикой.
Причина — требование локализации персональных данных, см. `compliance.md`.

## Себестоимость

Ориентировочно на минуту разговора:
- **STT** (Yandex SpeechKit, телефонная модель) — несколько ₽/мин.
- **LLM** (Claude, короткие реплики с function calling) — переменная, но при
  коротких репликах сопоставимо или дешевле STT.
- **TTS** — тарификация по символам, обычно сопоставимо со STT.
- **SIP/телефония** — тариф оператора за минуту (входящие обычно дешевле
  исходящих/международных).

Закладывать в тариф клиенту себестоимость с запасом ×3–5 на старте, уточнить
точные цифры тестовыми звонками на этапе пилота.

## Ключевые технические риски

- Латентность STT→LLM→TTS ощущается как неестественная пауза в разговоре —
  использовать стриминговый STT/TTS и короткие фразы-заполнители.
- Обработка прерываний (barge-in) — клиент должен иметь возможность
  перебить агента, как в разговоре с человеком.
- Качество распознавания узбекской речи — не полагаться на одного
  провайдера без сравнения.
